# Ending a timed AMRAP early: established-app wording

## Question and short answer

What do established workout apps call the action that ends a timed AMRAP before its time cap, and what does the next screen ask for?

**No common, AMRAP-specific early-finish dialog was verified.** The directly verified vocabulary is **“Stop”** in WODProof's workout-recording instructions, **“SWIPE TO FINISH”** in a SmartWOD Timer promotional screenshot (its visible running timer is blue, matching the screenshot's FOR TIME option, not AMRAP), and **“Finish”** / **“Finish Workout”** in general strength loggers. Hevy explicitly separates **Finish → Save Workout → Save**. These are useful vocabulary precedents, not evidence that the apps share Blocklog's exact AMRAP flow. [S1–S4, S8–S10]

**Recommendation, not a competitor quotation:** rename Blocklog's dialog action to **“Stop and Add Reps”**. It names both the immediate effect and the next task, whereas “Save What I Did” suggests the later save has already happened. Blocklog already records rounds during play; its next form asks for **“Extra reps”**, displays **“Score”**, and leaves saving as a separate action. [L1]

## What the evidence supports for Blocklog

1. **Use a finishing/stopping verb for the stopping action, and reserve saving language for saving.** WODProof provides a directly quoted “Stop” precedent; Strong provides “Finish”; Hevy provides the clearest directly documented two-stage distinction, **Finish → Save Workout → Save**. None establishes a standard AMRAP early-stop dialog. [S4, S10, S12]
2. **Rounds plus remaining reps is an established score format, but not a verified shared post-stop screen.** SugarWOD and Wodify document that format; neither consulted source documents the timer-to-entry transition. BTWB's “Rounds & Reps” template has a different specific meaning. [S5, S6, S9]
3. **“Stop and Add Reps” is the best fit for the particular Blocklog action, not a label found in competitors.** It avoids promising a save, and avoids asking the user to re-enter rounds the app already counted. Keeping **“Finish early?”**, **“Discard”**, and **“Keep Going”** is compatible with that distinction; that is a wording judgment based on Blocklog's actual flow, not a claim about competitor dialogs. [L1]

## Limits

No app runtime was tested, and no competitor's exact **AMRAP-before-time-cap → confirmation → rounds/extra-reps form** sequence was verified end to end. Consequently there is no supported majority claim about an early-finish button or dialog, and no basis to say that any competitor uses “Stop and Add Reps.” The recommendation is a fit-to-behavior judgment supported by adjacent established wording, with all missing interaction details left **unknown**. No code was changed, and this file is left uncommitted.
